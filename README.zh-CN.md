# LongChat Perf

**一个让长 ChatGPT 对话保持流畅的轻量本地渲染补丁（浏览器扩展）。**

```
无网络请求。  无统计埋点。  不删除任何消息。
```

📊 **实测效果：切换长会话最长冻结 8.5s → 1.1s（-87%），累计阻塞 -52%** → [完整数据见「验证效果」](#验证效果可选)

核心 JS 约 700 行。无框架、无构建步骤、运行时零依赖。

## 这个扩展**不**做什么

- 不导出对话
- 没有任何 AI 功能
- 无统计埋点
- 无后端
- 无账号体系
- 不删除 DOM 节点
- 无构建框架

它是一个单一用途的渲染补丁：长对话会随消息全部驻留在 DOM 中而逐渐变卡，
LongChat Perf 负责减少"你当前没在看的内容"的渲染开销。

## 安装

当前仅以源码形式分发，两步即可：

1. 下载本仓库 ZIP（或 `git clone`）。
2. 打开 `chrome://extensions`（Edge 为 `edge://extensions`），开启**开发者模式**，
   点击**加载已解压的扩展程序**，选择 `longchat-perf/` 文件夹。

无需构建、无需包管理器、无需注册。

## 原理

content script 提供五个可选补丁，均可通过工具栏弹窗单独开关（也可整体停用）。

| 补丁 | 作用 |
|---|---|
| **屏外渲染跳过** | 给消息与代码块元素应用 `content-visibility: auto` + `contain-intrinsic-size`，浏览器跳过视口外内容的布局与绘制（Chromium 85+、Firefox 125+、Safari 18+）。 |
| **中和毛玻璃** | 作为可选的高强度性能补丁禁用 `backdrop-filter`，避免滚动时毛玻璃表面逐帧合成图层。 |
| **旧消息渐进折叠** | 向下滚动时，将视口上方至少两屏之外的消息以 CSS 折叠为零高度，收进一条提示条；向上滚动即全部展开。 |
| **流式输出节流** | 回答流式输出期间暂停消息区的动画与过渡，降低每个 token 到达时的合成开销。 |
| **代码块批量挂载**（v0.2） | 打开/切换会话时，把同一批创建的 CodeMirror 代码编辑器合并到一次挂载，将 N 次整页样式重算摊销为 1 次（需 Chrome 111+）。 |

### 代码块批量挂载的行为约定

长会话里最重的 DOM 是代码块（CodeMirror 6 编辑器）。打开或切换会话时，
React 会一次性挂载数十上百个编辑器实例，每个都在已连接文档状态下触
发整页样式重算 —— 这是「切会话卡死几十秒」的直接元凶。

补丁原理：CodeMirror 构造器把「尚未完成初始化」的编辑器根节点插入文
档后，才设置其类名与属性。本补丁在插入前把这批根节点暂扣在游离状态
（游离子树不触发整页样式失效），合并到同一个任务里统一插入 —— 实测
147 个编辑器的会话切换从 42 秒长任务降到总忙时约 2–3 秒。

- 该补丁运行在页面主世界（`content_scripts[].world: "MAIN"`，
  Chrome 111+；旧版浏览器上自动不生效，不影响其他补丁）。
- 指纹不匹配一律透传原生行为；ChatGPT 改版导致指纹失效时会**安全退化**
  为不拦截，并在弹窗里提示「补丁疑似失效」。
- 若检测到 Tampermonkey 版同类补丁（`__CHATGPT_CM_PERF_FIX__`）在场，
  本补丁自动让位，避免双重拦截。
- 弹窗实时显示拦截统计：已拦截/挂载编辑器数、批次数、上批挂载耗时，以及内置
  **本地长任务监视**（仅内存统计，不上传）：>50ms 主线程任务的累计/最长时长，
  及每批挂载后的伴随长任务时长。

## 验证效果（可选）

弹窗底部的「长任务监视」可直接量化收益：

1. 开启补丁，切换几个长会话，记录「累计 / 最长 / 本批后」数值；
2. 关闭「代码块批量挂载」开关，刷新页面后切换同样的会话，对比数值增长；
3. 两者之差即补丁节省的主线程阻塞时长（长任务 >50ms 才计数，刷新后归零）。

**真机实测（2026-08，Chrome，~624 个编辑器的多个长会话）：**

| 指标 | 开启 | 关闭 | 改善 |
|---|---|---|---|
| 累计长任务 | 20.0s | 41.4s | **-52%** |
| 最长单次冻结 | 1.1s | 8.5s | **-87%** |
| 拦截率 | 624/624（9 批） | — | 100% |

另在 147 编辑器的冷会话上用 CDP trace 实测：开启后单批挂载仅伴随
~2-3s 主线程忙时，而关闭时为单条 42.4s 长任务。

金标准可用 DevTools → Performance 录制切换过程做开关对比；页面控制台
`window.__LCP_CM_MOUNT__.state()` 可直接读取全部统计。

### 折叠的行为约定

- 折叠是**渐进且由滚动驱动**的：只在您向下滚动时发生，且只碰远离视口的历史消息；
  扩展绝不会在后台自行折叠内容。
- **向上滚动立即全部展开**，且不会移动您正在阅读的内容。
- 任何一次展开后有 8 秒冷却，避免折叠/展开反复抖动。
- 对话顶部的提示条可一键跳到最早的消息。

**关于折叠的边界说明：** 它主要减少布局/绘制/渲染开销，而非真正虚拟化或删除
DOM 节点。它不删除 ChatGPT 托管的消息节点；折叠基于 CSS 且可逆。消息节点、
React 状态与 JS 内存始终保留。

**兼容性：** ChatGPT 前端是闭源的且会持续变化。脚本通过稳定的 DOM 属性
（`div[data-message-author-role][data-message-id]`）定位消息。如果 ChatGPT
改变渲染策略或 DOM 结构，可能需要重新验证兼容性。
